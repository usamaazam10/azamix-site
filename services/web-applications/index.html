{% include section-head.html no="01" label="Problems it addresses" id="problems-title" title="When a website stops being enough." %}

  • Customers have to ask you for everything

    Order status, invoices, documents and account changes all go through email or phone. A customer portal lets them help themselves, and frees your team for questions that need a person.

  • Your team manages records in shared files

    An admin dashboard with search, filters, permissions and history replaces the shared spreadsheet and the "who changed this?" conversations.

  • You have a product idea that runs in the browser

    A SaaS product needs accounts, billing and per-customer data separation built in from the first version, not bolted on later.

  • An existing application is slow or fragile

    Pages take seconds to load, and changes break unrelated features. Performance work and gradual restructuring can often fix this without starting over.

{% include section-head.html no="03" label="Use cases" id="fit-title" title="Web app, website or mobile app?" %}

A good fit when

  • People need to log in and work with their own data
  • Your team or customers use it on a mix of devices
  • You want one system that a mobile app or partners could use later
  • You're launching a subscription software product

Probably not needed when

  • You need a brochure site; a website builder will do
  • A well-known SaaS product already does the job
  • Users mostly need it offline or on the move; consider a mobile app
{% include section-head.html no="04" label="Technical considerations" id="tech-title" title="What happens under the interface." %}

Authentication and permissions

Every request is checked on the server: who the user is, and whether their role allows this action on this record. Hiding a button in the interface isn't security; the API enforces the rules.

Performance

We measure load times on ordinary phones and connections, not only on developer laptops. Database queries are indexed, large lists are paginated, and heavy work runs in background jobs so pages stay responsive.

Accessibility

Keyboard navigation, focus states, labels, contrast and screen reader support are built in from the first screen. Accessible applications are also easier for everyone to use.

Data separation for SaaS

When one application serves many customers, every query must be scoped to the right customer. We design this into the data model and test it, because a leak between customers is the most damaging bug a SaaS product can have.

Maintenance

Frameworks and libraries release security updates continuously. An application that isn't updated accumulates risk. Ongoing maintenance, monitoring and improvements can be agreed separately. See Cloud, Deployment and Ongoing Engineering Support.

Ownership

Ownership of code and deliverables is set out in the project agreement. Handover includes the source code, documentation, and instructions for deploying and running the application.
